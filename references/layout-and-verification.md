# 缩进恢复与核验

## 先建结构，再生成 XML

对每张 slide 建立简短结构记录。以下为虚构的层级示例：

```json
{
  "pdf_page": 1,
  "slide": 1,
  "title": "示例标题",
  "items": [
    {"text": "一级条目", "children": [
      {"text": "二级条目A"},
      {"text": "二级条目B"},
      {"text": "二级条目C", "children": [
        {"text": "三级条目"}
      ]}
    ]}
  ]
}
```

PDF 页码和 slide 编号仅用于内部核验，不写进飞书提示标题。该记录只演示父子关系，并非任何页面的固定模板。实际从原图/原生段落读取，每张 slide 独立判断。

对应飞书 XML：

```xml
<h3>示例标题</h3>
<ul>
  <li>一级条目
    <ul>
      <li>二级条目A</li>
      <li>二级条目B</li>
      <li>二级条目C
        <ul>
          <li>三级条目</li>
        </ul>
      </li>
    </ul>
  </li>
</ul>
```

## 常见失真及处理

| 失真 | 处理 |
| --- | --- |
| 所有 ◆、□、➢ 被删掉后变成同级列表 | 在清理符号之前记录层级，从原图恢复父子树 |
| 换行后的内容与前行横坐标不同 | 判断是否悬挂缩进续行，先拼回原项 |
| 左右两栏交替混排 | 先划分栏/文本框，再各自恢复阅读顺序 |
| 标题与项目符号高度接近 | 根据原图字号、位置和段落关系，不仅靠第一行判断标题 |
| 每个 li 单独包 ul，子项写成相邻 ul | 连续同级项共用列表，子列表放父 li 内部 |
| 用多个空格模拟列表缩进 | 改成语义嵌套列表；空格在云文档中可能折叠 |
| 代码被当作一般缩进列表 | 使用 pre/code，保留代码块内部空白 |
| 公式单独成段导致脱离所属子项 | 当前 XML 支持时放入所属 li 内；不支持时保持邻接并记录对应关系 |

## 实际验证方法

1. 本地 XML 用临时根节点解析，检查标签闭合与转义。XML 合法不等于结构正确。
2. 对多级列表逐项比较来源结构记录和生成 XML：每个列表项的文本、父项、深度、顺序。记录实际对应关系，而非只数列表项数量。
3. 写入后 fetch 对应 section 的 full XML，用同样方式比较父子关系。飞书可能合并连续列表，比较语义树而不是字节级字符串。
4. 不应通过查找所有后代文本来判断父项内容，否则会把子项内容重复算入父项；只比较该 li 的直接行内内容与其独立 children。
5. 发现被拍平时，在已授权范围内对本次新增的小范围文本块修复，避开原有图片和批注，修复后再次回读。涉及不同父级、不可重建资源或不确定块范围时，先重新定位而非全文覆盖。
6. 验收报告分别记录内容完整性、层级结构和实际视觉检查结果。没有视觉检查就不写“显示完全一致”。
