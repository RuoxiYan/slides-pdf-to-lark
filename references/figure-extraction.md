# 从课件中提取图片并就地插入

## 工具选择

- 用户已下载的工具优先检查其本地 README、运行环境和使用方式；不要仅凭项目名字假定支持全部课件图片。
- 如需参考 PDFFigures 2.0，可阅读其官方仓库；不要求用户安装它。本项目的提取脚本独立使用 PyMuPDF，不依赖 PDFFigures 2.0。
- PDFFigures 2.0 根据图注识别论文的图表，输出页号（从 0 开始）、图和图注的边界框。课件中的无图注图片、多图拼版、旋转文字可能漏检。先用代表页试提取并与原页比较，不能把“返回零张”当成“页面没有图片”。具体参数按本地 README/CLI 核实。
- 直接读取 PDF 嵌入图像可使用可用的 PyMuPDF 或 Poppler pdfimages；同时需要页面坐标与出现位置映射，不能只导出一堆无来源文件。不要假设环境已装 PyMuPDF。
- 对矢量图、多个图片对象组成的图、由文本对象组成的图轴/图例，使用 PDF 局部高分辨率渲染。原始图像提取若丢了标签、透明蒙版、旋转/裁切或叠加文字，就改用局部渲染，不能强求直接导出。

## 提取流程

1. 识别单张 slide 的区域，再识别图表区域。每个候选图记录 PDF 页、slide 位置、bbox、对应段落及插入锚点。
2. 提取或渲染到工作目录。将包含透明蒙版的图正确合成，确认方向、颜色与 PDF 可见内容一致。
3. 局部裁切保留整张图的标题、坐标、图例、显著性标记和出处，避免裁去边缘或混入相邻 slide。必要时包含图注；不使用整页讲义图充当图表。
4. 排除重复的学校标志、装饰横幅、背景纹理等模板素材，保留有教学含义的图片。图片文件可以复用，但同一图片在不同论述位置出现时不要误删该处引用。
5. 目视核验每个实际插图：无黑底/蒙版错误，无缺字、裁边或错误对应。不把内嵌公式图片误当装饰删除；能可靠转成可编辑公式则优先转录。

## 对应文字位置

- 以原课件局部阅读顺序为准：图在解释段落后就放在该段后；图中嵌入文字说明则保留完整图。
- 优先使用已核实的精确块位置。若通过 `docs +media-insert` 的文字选择插入，检查当前 CLI 对嵌套列表的行为；可能插到顶层祖先之外。必要时查支持的块级接口或在整段嵌套列表后紧邻插图，并回读/预览验证。
- 不把所有图片统一追加到文档末尾。顺序构建新内容时，可以先写相关文本、插图，再写后续文本。
- 正文可用原图题或“图：……”作为必要图注；不显示内部文件名、bbox、PDF 页码说明、提取工具名称。
- 验收时逐图检查来源、位置、清晰度和文本对应，不能以图片总数等于某个期望数代替检查。

## 修订已有转录

用户明确要求修改已有文档时，先读取当前结构。只删除本次转录产生的页码提示标题、整页附图及悬空说明，保护课件本身的主题标题和用户图片/批注。旧整页图可能是某些图表唯一的保留位置：先完成局部提取和替代插图，再移除旧整页图，最后核验没有内容遗失。对原有“见本页原图”等引用逐一改为对应局部图的说明。未获得修改已有文档的明确意图时，只更新技能，不触碰历史文档。

## 已提供的本地提取工具

使用 [../scripts/extract_slide_figures.py](../scripts/extract_slide_figures.py)，依赖 `PyMuPDF >= 1.24`。先检查当前 Python 是否能 `import pymupdf`；缺失时安装到任务工作目录的依赖目录，用 `PYTHONPATH` 引用，不假设某个旧会话的临时依赖仍存在。

```bash
python3 -m pip install --target work/pdf-image-deps 'pymupdf>=1.24'
PYTHONPATH=work/pdf-image-deps python3 /path/to/skill/scripts/extract_slide_figures.py lecture.pdf --out work/figures --pages 1,2,3
```

- `--out` 必须是尚不存在的新目录，避免覆盖已核验结果。省略 `--pages` 处理全部页面，页码从 1 开始。
- `assets/xref-*` 是原生图片对象；有蒙版时合成为透明 PNG，同一对象只导出一次、保留多个出现位置。
- `assets/p*-f*.png` 是候选区域的局部渲染，组合保留图片、文字、线条。并非所有候选都需要转成图片，公式仍应尽量转为可编辑公式。
- `manifest.json` 保存来源校验值、图片对象、坐标、slide 区域、候选图、附近文字；附近文字只是位置线索，不是已确认的正文插入锚点。
- `review.html` 展示局部图和页内位置，完整原页预览只用于本地核验，不能上传为飞书整页附图。
- `review_status=pending` 表示尚未核验。**不能自动把全部候选插入飞书**。

算法会优先识别讲义中有矩形白底的横向 slide 区域，过滤长横幅和极小碎片，把相邻图形组合成候选。它不依赖论文图注，也不是经过训练的视觉模型。无边框/异形背景的 slide、密集图文、组合标题和相邻正文可能误分，检测得到的区域数量不能直接作为实际幻灯片数量。应逐页检查位置预览，必要时传入人工核对的区域配置。

### 修正图表或 slide 边界

使用 `--regions regions.json`。所有边界框以 PDF 未旋转坐标为准：左上角为原点，单位 point（72 point = 1 inch），格式 `[x0,y0,x1,y1]`；不能直接填屏幕截图像素。

```json
{
  "slides": [{"page": 1, "bbox": [0, 0, 600, 400]}],
  "figures": [{"page": 1, "bbox": [40, 70, 160, 150], "title": "原有图题", "after_text": "该图对应的原文段落"}]
}
```

以上为虚构坐标，配置只是格式示例，坐标不能直接沿用。某页配置了 slides 则该页使用指定的完整 slide 区域列表；某页配置了 figures 则替换该页自动图表候选，必须列全该页需要输出的图。没有配置的页仍使用启发式检测。每次修正输出到新目录，再比较预览。
